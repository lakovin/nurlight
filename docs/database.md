# База данных

Бот и панель работают с одной базой. Таблицы описаны моделями Django в
`admin_panel/delivery/models.py`, бот использует эти же модели через ORM
(`bot/services/db.py`). Меняем схему только в моделях и через миграции:
`python manage.py makemigrations && python manage.py migrate`.

## Таблицы

| Таблица | Поля | Связи |
|---|---|---|
| Client | telegram_id (уникальный), name, phone, language (ru/kk), registered_at | — |
| Category | name, sort_order | — |
| Product | name, description, price, is_available | → Category |
| Order | status, address, total, comment, created_at, updated_at | → Client, → Courier (может быть пустым) |
| OrderItem | quantity, price (цена на момент заказа) | → Order, → Product |
| Courier | name, phone, telegram_id (можно пустым), is_active | — |
| FAQ | question, answer, language (ru/kk) | — |

Номер заказа для клиента — это id в формате `000042`.

## Статусы заказа

| Код | Название | Кто ставит |
|---|---|---|
| new | Новый | бот, при подтверждении заказа |
| accepted | Принят | оператор |
| handed_to_courier | Передан курьеру | оператор, при назначении курьера |
| in_transit | В пути | оператор или курьер |
| delivered | Доставлен | оператор или курьер |
| cancelled | Отменён | оператор; клиент — пока заказ «новый» |

## Решить на созвоне

1. Категории: отдельная таблица Category (сейчас) или текстовое поле у товара, как в ТЗ.
2. Телефон клиента: спрашиваем при /start или при первом заказе (кнопка «Поделиться контактом»).
3. Адрес: одна строка текста или ещё и геолокация (широта/долгота) — нужно для расчёта доставки по расстоянию.
4. Стоимость доставки: отдельное поле в Order или включена в total.
5. Кто может отменить заказ и до какого статуса.
6. Уведомления о смене статуса: панель сама отправляет сообщение через Telegram API, или бот периодически проверяет изменения.
7. Курьер: получает уведомления в Telegram и меняет статус сам, или статусы меняет только оператор.

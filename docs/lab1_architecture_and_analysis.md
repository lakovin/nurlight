# Лабораторная работа №1 по Web-разработке
**Тема проекта:** «Разработка Telegram-бота для автоматизации приёма заказов и обслуживания клиентов службы доставки» (Nurlight Delivery Bot)  
**Команда:** Nurlight (Нурдаулет, Нурадыл, Ислам)  
**Роль Студента 1:** Аналитик (анализ предметной области, архитектурные требования, конкурентный анализ, сценарии процессов)

## 1. Введение и актуальность

### 1.1. Проблематика
Для локальных служб доставки, кафе и малого бизнеса ключевым каналом коммуникации являются мессенджеры и телефонные звонки. Ручной прием заказов приводит к ряду критических проблем:
- Высокая нагрузка на оператора в пиковые часы.
- Человеческий фактор: ошибки в адресах, составе заказа, потеря сообщений в диалогах.
- Долгое ожидание ответа со стороны клиента.
- Отсутствие прозрачного трекинга статуса заказа в реальном времени.

### 1.2. Цель и задачи проекта
- **Цель:** Сократить время обработки заказов и операционные затраты за счет внедрения Telegram-бота для клиентов и единой веб-панели управления для операторов.
- **Пользователи системы:**
  - **Клиент:** оформление заказа, просмотр каталога, онлайн-отслеживание статуса.
  - **Оператор (веб-панель):** модерация заказов, назначение курьеров, управление каталогом.
  - **Курьер:** получение уведомлений о назначенных заказах, смена статуса доставки.
  - **Руководитель:** статистика продаж, отчетность по выручке и времени доставки.

## 2. Анализ бизнес-процессов

### 2.1. Процесс «Как есть» (AS-IS) — Ручная обработка
1. Клиент пишет в WhatsApp/Telegram или звонит оператору.
2. Оператор вручную консультирует по позициям меню/каталога и ценам.
3. Оператор записывает адрес, контакты и состав заказа в блокнот/таблицу Excel.
4. Оператор связывается с кухней/складом, затем звонит/пишет курьеру.
5. Для уточнения статуса клиент снова пишет/звонит оператору, отвлекая его от новых заказов.

### 2.2. Процесс «Как будет» (TO-BE) — Автоматизация через Nurlight
1. Клиент запускает Telegram-бот (`/start`), открывает интерактивное меню/каталог, собирает корзину.
2. Указывает адрес и телефон (ввод или отправка контакта в 1 клик), подтверждает заказ.
3. Заказ мгновенно фиксируется в базе данных PostgreSQL со статусом `новый`.
4. В веб-панели оператора в реальном времени появляется новый заказ со звуковым/визуальным уведомлением.
5. Оператор подтверждает заказ (`принят`) и назначает свободного курьера (`передан курьеру`).
6. Бот автоматически отправляет клиенту push-уведомление о смене статуса.
7. Курьер доставляет заказ, заказ переходит в статус `доставлен`.

## 3. Конкурентный анализ

Для обоснования разработки собственного решения проведён сравнительный анализ существующих альтернатив на рынке:
1. **Глобальные агрегаторы (Glovo, Wolt, Яндекс Еда)**
2. **Типовые готовые конструкторы ботов (BotMan, Salebot, LeadConverter)**
3. **Решение Nurlight Delivery Bot (кастомная разработка: aiogram + Django)**

| Критерий сравнения | Агрегаторы (Glovo / Wolt / Яндекс) | Конструкторы чат-ботов (No-Code/SaaS) | Наше решение (Nurlight Delivery Bot) |
| :--- | :--- | :--- | :--- |
| **Комиссия за каждый заказ** | Очень высокая (**20% – 35%** от чека) | Ежемесячная подписка + лимиты на сообщения | **0% комиссии**, владение собственной платформой |
| **Собственная клиентская база** | Клиенты принадлежат агрегатору (прямого доступа к аудитории нет) | Доступны базовые контакты | **100% владение базой данных клиентов**, возможность прямых рассылок |
| **Порог входа для клиента** | Требуется установка отдельного тяжелого приложения и регистрация | Работает внутри мессенджера | **Внутри Telegram**, без установки приложений |
| **Кастомизация под бизнес-процессы** | Жестко фиксированные правила агрегатора | Ограничена шаблонами конструктора, сложно интегрировать сложную логику | **Полная гибкость:** любые правила ценообразования, роли, кастомная аналитика |
| **Панель диспетчера / оператора** | Встроенный терминал агрегатора | Простая таблица сообщений, нет полноценного диспетчерского центра | **Полноценная веб-панель (Django)**: фильтры, смена статусов, учет курьеров, права доступа |
| **Стоимость владения** | Постоянные огромные отчисления от выручки | Ежемесячная подписка (10 000 – 30 000 KZT/мес) | **Минимальная:** оплата только за хостинг/сервер (VPS) |

### Вывод по анализу:
Для малого и среднего бизнеса агрегаторы забирают критическую часть маржинальности (до трети стоимости заказа), а no-code конструкторы не дают надежной синхронизации с единой базой данных и полноценной панели диспетчера. Разработка собственного Telegram-бота с бэкендом на Django и СУБД PostgreSQL — оптимальный баланс между стоимостью владения, безопасностью данных и удобством клиента.

## 4. Системная архитектура (System Architecture)

Система построена по модульной архитектуре с единым источником правды — реляционной базой данных PostgreSQL.

```
                      +-----------------------------+
                      |       Клиент (Telegram)     |
                      +--------------+--------------+
                                     |
                                HTTPS (API Telegram)
                                     |
                      +--------------v--------------+
                      |   Telegram Bot (aiogram 3)   |
                      |  - FSM сценарии (диалоги)   |
                      |  - Обработка каталога       |
                      |  - Push-уведомления         |
                      +--------------+--------------+
                                     |
                                (asyncpg / ORM)
                                     |
+---------------------+              v              +---------------------+
| Оператор / Директор | ----> [ PostgreSQL DB ] <---- |     Django Admin    |
| (Браузерная панель) |      (Единая база данных)    |  - Модели и связи   |
+---------------------+                             |  - Авторизация/RBAC |
                                                    |  - Аналитика заказов|
                                                    +---------------------+
```

### Компоненты системы:
1. **Telegram Bot Engine (aiogram 3):**
   - Асинхронная обработка сообщений.
   - FSM (Finite State Machine) для пошагового сбора адреса, телефона и комментариев к заказу.
2. **Web Admin Panel (Django):**
   - Управление каталогом (добавление блюд/товаров, категорий, цен).
   - Мониторинг заказов, изменение статусов: `Новый` -> `Принят` -> `Передан курьеру` -> `В пути` -> `Доставлен`.
   - Разграничение прав (RBAC): Оператор, Администратор / Руководитель.
3. **Database (PostgreSQL):**
   - Единая нормализованная схема: `Clients`, `Products`, `Orders`, `OrderItems`, `Couriers`, `FAQ`.

# Nurlight Delivery Bot

Дипломный проект команды Nurlight: сайт и Telegram-бот, через которые клиенты службы доставки
оформляют и отслеживают заказы, и веб-панель на Django, где операторы их обрабатывают.

Бот (aiogram 3) и панель (Django) работают с одной базой данных. Таблицы описаны
моделями Django в `admin_panel/delivery/models.py`, а бот использует эти же модели через ORM.

## Структура

```
bot/                  # Telegram-бот (aiogram 3)
├── main.py           # точка входа
├── handlers/         # обработчики: /start, каталог
├── keyboards/        # кнопки
├── states.py         # FSM-состояния оформления заказа
└── services/         # работа с базой
admin_panel/          # Django-проект
├── manage.py
├── config/           # settings, urls
├── delivery/         # модели, admin.py, демо-данные
└── shop/             # сайт для клиентов: каталог, корзина, оформление, статус заказа
docs/                 # схемы, требования, сценарии диалогов
```

## Запуск

Нужен Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # вписать BOT_TOKEN от @BotFather
```

Для разработки проще всего SQLite — в `.env` укажите `DATABASE_URL=sqlite:///db.sqlite3`.
Для PostgreSQL — строку вида `postgres://user:password@localhost:5432/nurlight`.

Создать таблицы и заполнить демо-данными (каталог, курьеры, ~60 заказов за 2 недели,
пользователи `manager` и `operator` с паролем `nurlight-demo`):

```bash
cd admin_panel
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser   # свой администратор, по желанию
```

Тесты: `cd admin_panel && python manage.py test delivery shop`.

Сайт для клиентов (http://127.0.0.1:8000/) и панель (http://127.0.0.1:8000/admin/):

```bash
cd admin_panel
python manage.py runserver
```

Бот (из корня репозитория):

```bash
python -m bot.main
```

## Статусы заказа

новый → принят → передан курьеру → в пути → доставлен; отдельно «отменён».

## Роли в панели

Группы создаются автоматически при `migrate`. Чтобы выдать роль, в разделе «Пользователи»
отметьте «Статус персонала» и добавьте пользователя в группу.

| Роль | Что может |
|---|---|
| Оператор | заказы: просмотр, создание, смена статуса, назначение курьера; клиенты; справочники — только просмотр |
| Руководитель | всё в разделе «Доставка», включая удаление и страницу статистики |

## Что уже есть

- модели: Client, Category, Product, Order, OrderItem, Courier, FAQ;
- панель заказов: фильтры по статусу, курьеру и дате, поиск, смена статуса и курьера прямо в списке,
  массовые действия «Принять» и «Отменить»; при назначении курьера заказ сам переходит
  в «Передан курьеру», сумма пересчитывается по позициям;
- статистика для руководителя (кнопка «Статистика» над списком заказов): заказы, выручка,
  средний чек, доля отмен, график по дням, статусы, популярные товары, курьеры;
- бот: `/start` (регистрирует клиента) и каталог по категориям;
- сайт для клиентов (макет — файл «Nurlight — сайт для клиентов» в Figma): главная, меню с категориями
  и поиском, корзина, оформление заказа без Telegram, страница статуса по номеру заказа и телефону.
  Клиент с сайта находится по телефону: если он уже писал боту, заказ попадает в ту же карточку.
  Контакты в подвале и кнопка бота задаются в `.env`: `SHOP_PHONE`, `SHOP_HOURS`, `TELEGRAM_BOT_USERNAME`.

## Граф кода (graphify)

В репозитории настроен [graphify](https://github.com/Graphify-Labs/graphify): он строит граф
знаний по коду и документам, и Claude Code ищет по нему, а не читает файлы подряд. Настройки
лежат в `.claude/` и `CLAUDE.md`. Сам граф (`graphify-out/`) в git не хранится, каждый
собирает его у себя:

```bash
uv tool install graphifyy   # или: pipx install graphifyy (пакет с двумя «y»)
graphify update .           # собрать граф, ~3 секунды, без LLM и без затрат на API
graphify query "как оформляется заказ"   # пример запроса
```

Граф без Claude Code тоже можно посмотреть: откройте `graphify-out/graph.html` в браузере.
